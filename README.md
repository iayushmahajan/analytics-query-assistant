# Retail Analytics & Demand Forecasting Platform

Retail Analytics & Demand Forecasting Platform combines invoice-level exploration with a current economic forecast. Historical sales analysis and governed natural-language SQL use the [UCI Online Retail transactions](https://archive.ics.uci.edu/dataset/352/online%2Bretail) (CC BY 4.0); the one-month Germany retail outlook uses Eurostat's monthly `sts_trtu_m` retail trade volume index. These sources measure different things and are presented separately.

## What is in the application

- **Retail dashboard:** gross sales, sale invoices, units, monthly history, top products, country mix and data-quality counts.
- **Germany retail outlook:** a current, one-month forecast of the seasonally and calendar adjusted retail trade volume index (2021=100). A 24-month chronological validation window selects gradient boosting only when it materially beats the best of three transparent baselines. A later 24-month test window reports untouched MAE, WAPE, bias and empirical-range coverage.
- **Ask the data:** a Groq or Foundry Local model interprets a question into a typed Pydantic plan and PostgreSQL query. SQLGlot enforces a single read-only SELECT over `retail_lines`; the app structurally restricts sales metrics to positive, priced, non-cancelled invoice lines. The reader role, transaction, timeouts and result bounds provide additional controls.
- **Evidence:** returned rows, charts/tables, downloadable CSV, SQL and query scope. Insights are calculated locally from bounded result rows rather than generated by another model request. Results and recent history scroll into view after a question completes.

Both sources are public. The UCI importer does not store customer IDs. UCI gross sales are **not** net revenue after returns or profit, and the data has no costs, stock levels or curated product categories. The Eurostat index represents Germany's retail sector, not the sales or inventory needs of an individual company. Recent Eurostat observations can be provisional and revised.

## Run with Docker

Docker Compose is required. If `.env` already exists, preserve it and merge only missing values from [`.env.example`](.env.example). For a new installation, copy the example and set three distinct URL-safe database passwords (`openssl rand -hex 24`). Configure either Groq or Foundry Local below.

```bash
cp .env.example .env  # new installation only
docker compose up --build -d
docker compose --profile retail-data run --build --rm retail-data
docker compose --profile market-data run --build --rm market-data
```

Open **http://localhost:5173**. The API is proxied at `/api`, with OpenAPI docs at `/api/docs`. The `retail-data` command validates and imports UCI invoice lines. The `market-data` command fetches the filtered Germany series from Eurostat, validates its JSON-stat dimensions, replaces the previous snapshot atomically, records provenance and trains the forecast. Normal startup does not download or retrain, so rerun `market-data` when Eurostat publishes a new month.

Both importers support pinned offline reruns. Pass `--archive ... --expected-sha256 ...` to `app.scripts.import_retail`, or `--payload ... --expected-sha256 ...` to `app.scripts.import_market`. A checksum mismatch, unexpected dimension, invalid value, insufficient history or recent time-series gap fails before existing data is replaced.

**Existing installations:** migration `0004` permanently deletes the old synthetic sales tables and their saved query history. It preserves imported UCI retail rows and retail history. Back up any old synthetic records you want before starting the new backend. The old seed command and `/metadata` endpoint have been removed.

### Groq

Create a key in the [Groq console](https://console.groq.com/keys), then set these values in your untracked `.env`:

```dotenv
AI_PROVIDER=groq
AI_MODEL=openai/gpt-oss-20b
AI_API_URL=https://api.groq.com/openai/v1/chat/completions
AI_API_KEY=your_key_here
```

Recreate the backend with `docker compose up -d --force-recreate backend`. The key remains server-side. Groq's free tier has changing request/token limits; check the [official documentation](https://console.groq.com/docs/rate-limits). JSON object mode is followed by strict Pydantic validation and the SQL policy. Questions and schema context are sent to Groq, so do not enter confidential data.

### Foundry Local

Foundry Local provides a local OpenAI-compatible chat-completions endpoint with no model API charges. The port may change; run `foundry server status` to get its current URL. For example, if it prints `http://127.0.0.1:45779`, append `/v1/chat/completions`. For Docker Desktop connecting to a reachable Windows-host server, use `host.docker.internal` in place of `127.0.0.1`:

```dotenv
AI_PROVIDER=foundry_local
AI_MODEL=phi-4-mini
AI_API_URL=http://host.docker.internal:45779/v1/chat/completions
AI_API_KEY=
```

Start and load the model with `foundry server start --idle-timeout 0` and `foundry model load phi-4-mini`. When Foundry Local runs inside WSL bound only to loopback, Docker connectivity requires a reachable bind/proxy; a directly run WSL backend can use the reported loopback URL. Follow Microsoft's [Foundry Local CLI guide](https://learn.microsoft.com/en-us/azure/foundry-local/how-to/how-to-use-foundry-local-cli) for installation. Recreate the backend after endpoint changes.

## Query contract and security

`POST /query` accepts a question and up to three clarification turns. It rejects the retired `demo` dataset; the optional `dataset` field can only be `retail`. Ready plans require a canonical metric and SQL, while clarification/blocked plans cannot carry executable SQL. The only AI-queryable business table is `retail_lines`. Market observations, forecasts and import provenance are served through a fixed read-only endpoint and are not exposed to model-generated SQL. The model cannot access `query_history`, system catalogs or the removed synthetic tables. Every accepted query gets a bounded outer limit, restricted DB role, read-only transaction, timeout and result-size checks.

The semantic metric catalog is in [`backend/app/constants/metrics.py`](backend/app/constants/metrics.py). Sale lines have `is_sale=true`, meaning positive quantity and price on a non-cancelled invoice. This population is enforced by rewriting every actual `retail_lines` table source and validating again. This does **not** prove that every model-created calculation or grouping is business-correct; inspect its SQL and scope.

The main API routes are `GET /retail/overview`, `GET /retail/market-forecast`, `GET /examples`, `POST /query`, `GET /history`, `GET /history/{id}` and `GET /health`. History is a shared demonstration workspace, with no accounts or private workspaces. No result rows are sent to the provider during insight calculation.

## Development and verification

For direct development, install `backend/requirements-dev.txt`, configure owner and reader PostgreSQL URLs, run `alembic upgrade head` and `python -m app.scripts.apply_grants`, then start `uvicorn app.main:app --reload`. In `frontend`, run `npm ci && npm run dev`. Vite proxies `/api` to port 8000.

```bash
# backend
ruff check .
pytest -q

# frontend
npm run lint
npm test
npm run build
```

PostgreSQL integration tests require explicitly disposable `TEST_DATABASE_URL`, `TEST_ANALYTICS_DATABASE_URL` and `TEST_ALLOW_RESET=1`. Browser tests use mocked API responses and do not consume provider requests. Source datasets are downloaded only by explicit profile commands and are not committed to Git.

## Honest limits

This is a portfolio-grade analytics workbench, not a production multi-tenant BI platform. It has a small metric catalog, shared history and no scheduler, authentication, monitoring stack or automated model-drift response. The Eurostat pipeline is current and repeatable, but forecasts a national index rather than company demand. The validation/test split and expanding-window backtest measure historical performance; they cannot guarantee the next published value. A company-level demand claim would require a regularly refreshed company transaction and inventory feed.
